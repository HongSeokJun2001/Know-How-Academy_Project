## 관리자(학원장) **1차구현** 2차구현 3차구현

- **로그인 기능**
    - 로그인
        - **AJAX 방법으로 구현 하도록 다시 검토해야됨**
        - [Action]
            - 아이디/비번 입력 → 버튼 클릭
        - [Business Logic]
            - 프론트엔드에서 형식 및 빈값 1차 검증 (이메일이면 이메일형식인지)
            - 동시요청?
            - 서버로 adminId adminPwd 보냄
            - DB 에서 아이디로 사용자 정보 조회 (loginUser) + 로그인실패테이블정보조회
            - 비밀번호 BCrypt 해시 검증
            - 결과 검증 후 페이지 연결
                
                
                - CASE 1 (비밀번호 검증 통과)
                    - 조회결과가 없을 경우 (청정유저) 로그인성공
                    - 조회결과가 있고, 마지막 잠금시간+30분 <SYSDATE 일 경우 로그인 실패 횟수 0으로 초기화
                    - sessionScope 에 회원정보 저장(비밀번호제외 DTO)
                        - 비밀번호를 제외하고 DTO에 저장
                    - sessionScope 에 1회성 알림 문구 저장
                    - redirect:/
                    
                
                - CASE 2 (비밀번호 검증 실패)
                    - 조회결과가 없을경우 INSERT
                    - 마지막잠금시간+30 < SYSDATE AND 마지막실패시간+30분 < SYSDATE
                    일 경우 로그인 실패횟수 +1로 UPDATE
                    - 실패횟수가 4일경우 +1해주며 계정락 UPDATE
                    - 실패횟수가 1~3일경우 실패횟수 +1 UPDATE
                    
                    LoginPolicyHandler 클래스 별도로 만들어 로그인 검증하기
                    - requestScope 에 1회성 에러문구 저장
                    - 메인페이지로 포워딩
                    - 프론트엔드에서 에러 상황에 맞는 메시지 출력(비번오류, 계정락)
    - **[추후구현] 아이디 / 비밀번호 찾기**
        - 아이디찾기
        - 비밀번호찾기
    - [추후구현] IP로 계정락
        
        X-Forwarded-For 같은 헤더는 공격자가 요청을 보낼 때 가짜 IP를 임의로 적어서 보낼 수도 있어(IP Spoofing).따라서 무조건 헤더 값을 믿으면 안 되고, 백엔드 프레임워크 설정에서 **"내가 인증하고 신뢰하는 프록시 장비(예: 내 AWS 로드 밸런서)가 넘겨준 헤더만 인정하겠다"**라는 설정(trust proxy 옵션 등)을 반드시 켜야 안전하게 진짜 IP를 가려낼 수 있어
        
    - [추후구현] 가짜 암호화경로로 ID가 없을경우와 PWD가 일치하지 않는경우 응답시간 동일하게 맞추기
    - 로그아웃
        - [Action]
            - 버튼 + 클릭
        - [Business Logic]
            - 컨트롤러로 요청을 보냄
            - **session.invalidate()**
            - resquestScope 에 로그아웃 메시지 저장
            - 프론트엔드에서 메시지 출력
- 고객(학생)관리
    - 고객목록조회페이지
        - [UI / 화면 요소]
            - 고객 검색
                - 검색조건 : 드롭박스 ( 클래스/상담사/이름 )
                - 검색어 텍스트 필드
        - 비즈니스
            - 권한이 STUDENT인 사용자의 ID,이름,클래스를 조회
            - 클래스, 이름 이 목록에 뜨도록 함
            - 클릭시 사용자 ID가 전달되도록함
            - 리스트 정렬 기능
                - 클래스별 정렬 후 가나다라순으로 정렬
    - 고객상세조회페이지
        
        가입승인
        
        - 인적 사항 조회
            - 이름
            - 전화번호
            - 주소
            - 이메일
        - 상담 횟수 조회
            - 전체횟수(검정글씨) (n)
                - (n은 예약중인 상담이 있을 경우 횟수, 없을 경우 0으로 표시됨)
            - 기능 액션 (Action)
                - 전체 건수 클릭 시 담당 상담사 이름 뜸
                - 전체 건수 hover 시 담당 상담사 이름 뜸
                - (n) 에 hover 시 예약중인상담 이라는 안내문구 뜸
        - 메모 내용 조회
            - USERID로 페이지 내용 전체 조회
            - LEFT JOIN 조회결과 MEMO_CONTENT IS NULL 일 경우 INSERT “” 실행
            - 결과 성공시 조회결과를 프론트엔드에게 넘김
        - 메모 내용 수정[다른방식으로바꿀예정]
            - INSERT UPDATE DELETE 모두 ‘저장’ 버튼 하나로 통일
            - 실제 구현은 UPDATE 하나만 사용
            - 비즈니스로직
                - 저장버튼을 클릭할경우 스크립트 공간의 함수가 실행됨
                    - CASE1 : 되돌리기변수가 “” 인 경우
                        - 되돌리기변수 : 페이지로드시 DB에서 가져온 read 값이 저장됨
                        - 저장 : DB에 UPDATE 요청
                    - CASE2 : 되돌리기변수가 “”이 아닌 경우
                        - 되돌리기변수: 바로직전 저장값이 저장됨
                        - 저장 : DB에 UPDATE 요청
        - 메모 내용 되돌리기[다른방식으로바꿀예정]
            - 비즈니스로직
                - hover : 클릭 시 저장 전 상태로 되돌립니다. (※ [저장] 버튼을 다시 눌러야 내용이 저장됩니다.)
                - 초기값 비활성화 → 저장버튼 클릭시 활성화
                - 되돌리기버튼을 클릭 시
                    - 되돌리기버튼 비활성화
                    - 되돌리기변수에 저장된 값이 복구됨 (자동저장x)
        - 고객 삭제 (Soft Delete)
            - 버튼 클릭시 알람창으로 재확인 (이름, 확인)
            - 회원 ID 서버로 전송
            - SOFT DELETE 실행후 결과전달 → 목록페이지로 리다이렉트
        - 휴원 처리 (상태값 변경)
            - 버튼 클릭시 알림창으로 재확인 (이름, 확인)
            - 회원 ID 서버로 전송
            - 상태값변경 실행후 결과전달 → 상세조회페이지로 리다이렉트
            - 휴원회원일 경우 휴원표시와 함께 복구하기 버튼활성화 ㅠㅠㅠ
        - 휴원 취소 처리
            - 확인창 뜬다음 서버로 ID 전송
            - UPDATE 후 결과화면 리다이렉트
- 상담사(직원) 관리
    - 상담사 목록 조회 페이지
        - 상담사 이름으로 검색
            - 추가 카테고리 X
        - 리스트 정렬 기능
            - 이름으로 정렬
            - [추후 구현] 상담 실적별 정렬 기능
                - 비즈니스 로직
                    - 실적 테이블 생성 (분기별 갱신)
                        
                        상담사ID, 정산분기, 총상담횟수, 현재상담학생수, 성공건수, 최종실적등급 을 분기별로 산출하여 저장 및 제공
                        
                    - 총상담횟수
                        
                        상담상세내용테이블에서 상담사ID로 작성된 행의 개수를 COUNT(*) 하여 집계 
                        
                    - 현재상담학생수
                        - 학생테이블에 상담사 관련 속성 추가 (최초상담사ID, 현재상담사ID, 상담상태)
                        - 학생테이블의 상담상태 컬럼이 Y(진행중인상담) 인 학생들 중 상태 컬럼이 ‘퇴학’ ‘휴학’ 이 아닌 학생(재학, 비회원)만 현재상담사ID로 상담 건수 COUNT(*) 집계
                    - 성공건수(입학성공)
                        - 방안1 회원가입시 추천인목록에 상담사아이디를 적음
                            - 회원가입시 상담사 코드를 입력하게 구현
                            - 학생테이블에 최초상담사ID 컬럼에 들어가도록함
                        - 방안2 상담사가 링크를 비회원에게 제시, 링크를 통해 가입하면 자동으로 상담사 ID가 테이블로 들어옴
    - 상담사 상세조회
        - 퇴사처리(Soft Delete)
            - 화면 우측 상단에 빨간색 퇴사 버튼
            - 기능 액션 (Action)
                - 퇴사 버튼: 클릭 시 해당 상담사의 상태값 변화 (DB에서 데이터를 물리적으로 삭제하지 않음)
                - 클릭 시 경고창 띄우기
        - 상담사 사진 조회
        - 상담사 인적사항 조회
        - 상담사 역할 조회
        - 상담 일정 조회
    - 입사처리 (신규상담사계정등록)

            - 사용자 이름(입력)
            - 담당 상담 종류 (상담 카테고리 내 선택 - Select Box)
            - 아이디(필수/중복체크필요)
            - 비밀번호(필수/대소문자혼합8자리이상)
            - 비밀번호재입력(위와 동일)
        - 기능 액션 (Action)
            - 아이디생성(등록버튼)
        - 비즈니스 로직 (시스템 규칙)

            - 해당 상담사가 최초 로그인 시, 시스템이 status == 'TEMP’ 를 감지하여 메인 페이지가 아닌  추가 정보 입력 페이지 로 이동 시킴
